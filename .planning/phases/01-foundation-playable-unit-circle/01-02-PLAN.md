**.github/workflows/deploy.yml** (exact structure):
```yaml
name: Deploy
on:
  push:
    branches: [main, master]
  workflow_dispatch: {}
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: true
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 24
          cache: npm
      - run: npm ci
      - run: npm run check
      - run: npm test
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test
        env:
          CI: 'true'
      - run: npm run build
      - uses: actions/configure-pages@v6
      - uses: actions/upload-pages-artifact@v5
        with:
          path: build
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.d.outputs.page_url }}
    steps:
      - id: d
        uses: actions/deploy-pages@v5
```
Only first-party `actions/*` (supply-chain). No secrets are used or needed. (Playwright's webServer already runs `npm run build`; the explicit `npm run build` afterwards guarantees a fresh `build/` for upload.)

**static/CNAME**: single line `dm.ducksoft.ai` (adapter-static copies `static/` into `build/`). Do NOT add `static/.nojekyll` unless a deployed `_app/` asset 404s (Actions-based Pages deploys do not run Jekyll).

**docs/DEPLOY.md** — short checklist (max ~40 lines), sections: "One-time setup (you)": 1) create the GitHub repo (public), 2) `git remote add origin git@github.com:<user>/<repo>.git && git push -u origin master` (or rename to main first: `git branch -m master main`), 3) Settings -> Pages -> Source "GitHub Actions", 4) Settings -> Pages -> Custom domain `dm.ducksoft.ai`, 5) Cloudflare DNS: `CNAME dm -> <user>.github.io`, proxy status DNS only (grey cloud) until GitHub shows the certificate as issued, then optional orange cloud, 6) Cloudflare SSL/TLS mode **Full** (Flexible causes redirect loops), 7) GitHub Pages "Enforce HTTPS" once available. "How deploys work": push to default branch -> workflow runs check, unit, e2e, build -> deploys. "Notes": no server redirects on Pages; `/` language redirect is a static page (plan 01-03); unknown URLs get `404.html`; every route is a prerendered `index.html` (`trailingSlash: 'always'`). "Verify": `curl -sI https://dm.ducksoft.ai/en/` shows `200`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> Pages | CI builds and publishes the public artifact |
| Third-party actions -> CI | Action code executes with `pages: write` / `id-token: write` |
| DNS (Cloudflare) -> GitHub Pages | Domain ownership and TLS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | deploy.yml actions | mitigate | only first-party `actions/*` at pinned major versions; `permissions` limited to `contents: read, pages: write, id-token: write` |
| T-01-07 | Tampering | npm install in CI | mitigate | `npm ci` against committed package-lock.json |
| T-01-08 | Information disclosure | repo / workflow | mitigate | no secrets used; acceptance criterion greps for `secret` = 0 |
| T-01-09 | Spoofing | custom domain | mitigate | CNAME file + Pages custom domain verification; Cloudflare SSL "Full" + Enforce HTTPS (checklist) |
| T-01-10 | Denial of service | Pages hosting | accept | static CDN hosting; no server to overload; public educational content |
</threat_model>
